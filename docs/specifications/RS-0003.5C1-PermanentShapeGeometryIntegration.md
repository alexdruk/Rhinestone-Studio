# RS-0003.5C1 — Permanent Shape Geometry Integration

## Objective

Move circle and rectangle stone generation from the legacy in-`app.js` `GeometryEngine` class
into the permanent `src/geometry/GeometryEngine.js`, so text and shape layers both produce stones
through the same permanent Geometry Engine and the same `StoneLayout`/`Stone` data structures,
per `docs/ARCHITECTURE.md`'s single-source-of-truth principle.

## Current Repository State

* RS-0003.5B3 wired text layers to the permanent `src/geometry/GeometryEngine.js` via
  `generateTextLayout()`. Circle and rectangle layers still run through the legacy in-`app.js`
  `GeometryEngine.generateCircle()` / `generateRect()` (perimeter point placement + a local
  `dedupe()`), explicitly out of scope for that milestone.
* `src/text/VectorPath.js` already exports `createCircleVectorPath()` and
  `createRectangleVectorPath()` — deterministic helpers that build a closed `Contour` (4 cubic
  BÃ©ziers for a circle; 4 `lineTo`s for a rectangle) in millimeters. Both are already unit-tested
  in `tools/test-vector-path.mjs` but were not called from anywhere else in the repository before
  this task.
* `src/geometry/GeometryEngine.js` already contains `flattenContourToPolygon()` (via
  `ContourGeometry.js`) and `sampleOutlinePoints()` / `sampleFillPoints()` (via
  `StoneSampler.js`), used today only for text glyph contours. These are geometry-agnostic: they
  operate on any flattened polygon, not specifically glyph shapes.
* The permanent `GeometryEngine`'s constructor currently requires a `fontProviderRegistry` and
  throws if one is not supplied — a text-only requirement that would otherwise force shape-only
  projects to depend on font-manifest loading succeeding.
* `app.js`'s legacy `GeometryEngine` class stores the permanent engine instance as
  `this.permanentTextEngine`, reflecting its text-only role as of RS-0003.5B3.
* Shape layers are ad hoc plain objects (`{id,type,visible,cx,cy,r,...}` for circle;
  `{id,type,visible,x,y,w,h,...}` for rectangle) on `project.layers`, not instances of
  `src/core/Layer.js`. `app.js` does not use `src/core/**` (confirmed by existing guard tests) and
  this task does not change that.

## Expected Visible Change

* None of the manufacturing-relevant geometry changes in a way a user would find surprising: the
  2D layout, cup preview, and exports keep showing evenly spaced stones around the circle/rectangle
  outline at the same size/gap/color settings as before.
* Circle stones are placed on a 64-segment BÃ©zier-flattened approximation of the true circle
  instead of an exact trigonometric circle. At typical stone sizes/radii this is a sub-thousandth-
  millimeter deviation from a true circle (for example, on an 18&nbsp;mm-radius circle the maximum
  polygon-vs-circle deviation is about 0.003&nbsp;mm) and is not visually distinguishable. Exact
  stone count/positions may shift by a small amount compared to the legacy trigonometric placement
  because the two algorithms are not bit-for-bit identical, matching the RS-0003.5B3 precedent that
  exact stone count is not required to match the legacy baseline when the generation algorithm
  changes.
* Mouse-based add/select/drag/resize/duplicate/delete/visibility interactions for shape layers are
  unchanged in behavior; they edit the same plain-object layer fields (`cx/cy/r` or `x/y/w/h`) that
  feed the new generation path.

## Required Outcome

* Circle layers are generated via `GeometryEngine.generateShapeLayout({ shape: 'circle', ... })`.
* Rectangle layers are generated via `GeometryEngine.generateShapeLayout({ shape: 'rectangle',
  ... })`.
* Text layers continue to use `generateTextLayout()`, unchanged.
* Both code paths build stones as `Stone` instances assembled into a `StoneLayout`
  (`src/geometry/StoneLayout.js` / `Stone.js`) — the same classes, not parallel lookalikes.
* `generateShapeLayout()` reuses the existing `flattenContourToPolygon()` /
  `sampleOutlinePoints()` / `sampleFillPoints()` primitives (already used for text) via
  `createCircleVectorPath()` / `createRectangleVectorPath()` from `src/text/VectorPath.js` — no
  new sampling algorithm is invented.
* The permanent `GeometryEngine`'s constructor no longer requires `fontProviderRegistry`
  unconditionally; it becomes optional, and `generateTextLayout()` throws a clear error if called
  without one. This lets shape-only generation work even if font-manifest loading fails.
* `app.js`'s legacy `generateCircle()` / `generateRect()` are no longer called from `generate()`.
  They remain present, unused, per "do not remove the legacy engine until no live behavior depends
  on it" (`line()` is still shared with the legacy bitmap text stroke sampler, so the class is not
  yet fully separable).
* Stone size, gap, color, layer ID, bounding box, and deterministic output are preserved for
  circle and rectangle layers.
* Mouse-driven shape editing (add, select, drag-move, drag-resize, duplicate, delete, visibility
  toggle) continues to work unchanged — it edits the same plain layer fields consumed by the new
  generation path.
* The 2D layout, cup preview, Project JSON export, Generated Layout JSON export, SVG export, and
  PNG exports all continue to consume the single merged `layout.stones` array produced by
  `app.js`'s top-level `generate()` (text stones + shape stones + cross-layer dedupe/bbox), which
  is unchanged in shape.
* Coordinates stay in millimeters end to end.
* The project file format (`project.layers[].{cx,cy,r}` / `{x,y,w,h}`) does not change.

## Architecture Requirements

* `src/geometry/GeometryEngine.js`, `ContourGeometry.js`, and `StoneSampler.js` keep zero DOM,
  Canvas, or renderer/exporter dependency (already enforced by an existing test in
  `tools/test-geometry-engine.mjs`; unchanged by this task).
* `generateShapeLayout()` is a synchronous method (unlike `generateTextLayout()`, it does not
  await a font provider), but `app.js`'s call site awaits it like the text path for structural
  consistency and forward compatibility; awaiting a non-Promise value is harmless.
* `app.js`'s in-class field that held the permanent engine is renamed from `permanentTextEngine`
  to `permanentEngine` (and the matching `permanentTextEngineError` top-level variable to
  `permanentEngineError`), because it is no longer text-only. This is a same-file, contained rename
  directly required by this milestone's outcome, not a general cleanup.

* Deleting the legacy bitmap text engine or the now-unused legacy `generateCircle` /
  `generateRect` / shape `dedupe` path.
* Adding a fill mode for shapes in the UI (the permanent `generateShapeLayout()` API supports
  `mode: 'fill'` for completeness/reuse, but `app.js` only ever requests `'outline'`, preserving
  current shape behavior).

  appearance, cup drag rotation sensitivity, stone-size dropdown blank-selection bug) — record
  only.
* Any new dependency or bundler.
