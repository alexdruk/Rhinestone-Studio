# RS-0003.4 — OpenType Provider

## Status

Approved for implementation.

## Objective

Implement a real OpenType font provider behind the existing text provider architecture.

This task must not change visible UI behavior. It prepares the vector text engine for future stone generation.

## Expected visible change

None.

The app should look the same before and after this task.

## Allowed files

- `package.json`
- `src/text/*`
- `src/fonts/*`
- `tools/*`
- `docs/specifications/RS-0003.4-OpenTypeProvider.md`

## Forbidden files

Do not modify unless explicitly approved:

- `app.js`
- `index.html`
- `style.css`
- renderer files
- exporter files
- existing examples

## Requirements

1. Add an OpenType-compatible provider implementing the existing font provider interface.
2. The provider must load fonts registered by the Font Manager.
3. The provider must return vector-path-compatible glyph outlines.
4. Convert font units to millimeters.
5. Preserve deterministic output.
6. Add automated tests.
7. Update the `npm test` script to include the new tests.
8. Do not remove existing tests.
9. Do not change UI behavior.

## Architecture constraints

- Geometry Engine must not know about OpenType.
- Renderer must not know about OpenType.
- OpenType provider must return vector data only.
- All dimensions exposed to the rest of the app must be in millimeters.

## Suggested implementation files

- `src/text/OpenTypeProvider.js`
- `src/text/GlyphPath.js` if needed
- `tools/test-opentype-provider.mjs`

## Dependency policy

A dependency may be added only if necessary for parsing TTF/OTF files.

If adding a dependency, document it in the result package.

## Tests required

Run:

```bash
npm test
```

Tests should verify:

- provider registration;
- missing font handling;
- glyph path generation;
- bounding box in millimeters;
- deterministic output for the same text/font/size;
- no UI files changed.
