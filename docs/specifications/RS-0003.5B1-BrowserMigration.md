# RS-0003.5B1 — Browser Module Migration

Status: READY FOR SPECIFICATION REVIEW

Milestone: M3 — Vector Text

Branch: `feature/m2-vector-text`

---

## 1. Objective

Migrate the live Rhinestone Studio browser application from a single inline
script in `index.html` to a module-based application entry point in `app.js`.

This task is a **behavior-preserving migration**.

It does not yet replace the live bitmap text engine with the new vector
`GeometryEngine`. It only establishes the browser module structure required for
that later integration.

After this task:

```text
index.html
  └─ <script type="module" src="./app.js">

app.js
  ├─ owns application startup
  ├─ owns current UI event wiring
  ├─ owns current legacy runtime behavior
  └─ can import modules from src/**
```

The application must look and behave the same as before.

---

## 2. Current Repository State

The live application currently runs from one inline `<script>` block inside
`index.html`.

That inline block contains:

- application state,
- a legacy inline `GeometryEngine`,
- bitmap text generation,
- circle and rectangle generation,
- mouse editing for shapes,
- 2D production layout rendering,
- 3D cup preview logic,
- export logic,
- UI event wiring.

The existing root `app.js` is an orphaned prototype. It targets DOM element IDs
that do not match the live `index.html`, and `index.html` does not load it.

The permanent architecture under `src/**` already contains:

- project and layer models,
- font manager,
- font-provider registry,
- OpenType provider,
- vector path abstractions,
- vector text `GeometryEngine`,
- `Stone` and `StoneLayout`.

Those permanent modules are not yet connected to the live browser app.

---

## 3. Architectural Decisions

### 3.1 Live application shell

`index.html` remains the HTML document and UI markup.

It must not contain application business logic after this migration.

### 3.2 Application entry point

The root `app.js` becomes the browser entry module.

The old orphaned contents of `app.js` may be replaced.

### 3.3 No behavior change

All currently working behavior must remain available:

- text input,
- current bitmap font/mode behavior,
- circle creation,
- rectangle creation,
- mouse move and resize for shapes,
- layer management,
- production layout,
- cup preview,
- current exports,
- current project import/export.

### 3.4 Legacy engine preservation

The legacy inline engine may be moved into `app.js` unchanged or split into
small modules only when that split is mechanical and behavior-preserving.

Do not replace the legacy text engine in this task.

Do not connect the new `src/geometry/GeometryEngine.js` in this task.

### 3.5 Browser dependency strategy

This task must not import `OpenTypeProvider`, `opentype.js`, or any module that
transitively imports the bare specifier `opentype.js`.

No import map and no bundler are required for this migration task.

Browser loading of OpenType dependencies belongs to RS-0003.5B2.

## 4. Target Structure

Minimum required target:

```text
index.html
app.js
style.css
src/
```

`index.html` must load:

```html
<script type="module" src="./app.js"></script>
```

The page must no longer contain the live application implementation inline.

A small non-application inline script is allowed only when technically required
for bootstrapping, and must be documented.

## 5. Scope

Included:

- move live JavaScript from `index.html` into `app.js`,
- replace the old orphaned `app.js`,
- convert browser startup to ES module loading,
- preserve current DOM IDs and markup,
- preserve all current visible behavior,
- add automated structural tests,
- document the migrated entry point.

Not included:

- OpenType browser loading,
- import maps,
- bundlers,
- vector text integration,
- font-family selector,
- letter-spacing control,
- text auto-fit,
- shape-engine migration,
- renderer redesign,
- cup improvement,
- export redesign,
- product plugins.

## 8. Migration Procedure

1. Inspect the full inline application script in `index.html`.
2. Copy its complete behavior into the root `app.js`.
3. Resolve references that depended on script-global execution order.
4. Keep DOM queries and event bindings functionally equivalent.
5. Replace the inline application script with:
   `<script type="module" src="./app.js"></script>`.
6. Confirm the old orphaned `app.js` code is fully replaced.
7. Confirm no duplicate live application implementation remains in
   `index.html`.
8. Add tests that verify:
   - `index.html` loads `app.js` as a module,
   - the large inline application script is absent,
   - required live UI element IDs referenced by `app.js` exist,
   - `app.js` does not import OpenType or permanent GeometryEngine modules yet.
9. Run automated tests.
10. Start the application and complete manual regression QA.
