# RS-0003.5B3 — Live GeometryEngine Integration

## Objective

Connect the permanent `src/geometry/GeometryEngine.js`, `src/text/OpenTypeProvider.js` (via
`FontProviderRegistry`), and `src/fonts/FontManager.js` to live browser text generation in
`app.js`, so text layers are generated from real vector font outlines instead of the legacy
5x7 bitmap font. Shape layers (circle/rectangle) continue to use the legacy in-`app.js` engine.

## Current Repository State

* RS-0003.5B1 moved the whole application into `app.js` as an ES module with a self-contained
  legacy `GeometryEngine` class (bitmap text + shape generation).
* RS-0003.5B2 added an import map, a browser adapter for `opentype.js`, and a diagnostic
  `BrowserDependencyProbe` that proves the permanent module graph (`GeometryEngine`,
  `OpenTypeProvider`, `FontManager`) resolves in the browser — without using any of it.
* The permanent `src/geometry/GeometryEngine.js` exposes an async
  `generateTextLayout({ text, fontId, layerId, heightMm, stoneSizeMm, gapMm, letterSpacingMm,
  mode, color })` that returns a `StoneLayout` of `Stone { xMm, yMm, sizeMm, color, layerId }`,
  built through `FontProviderRegistry` → `OpenTypeProvider` → `VectorPath` → outline/fill
  sampling. It is fully tested (`tools/test-geometry-engine.mjs`,
  `tools/test-opentype-provider.mjs`, `tools/test-stone-color.mjs`,
  `tools/test-default-font-provider-registry.mjs`) but not yet called from `app.js`.
* `assets/fonts/manifest.json` registers three fonts. `CourierPrime-Regular.ttf` and
  `GreatVibes-Regular.ttf` are real, parseable TrueType files. `RobotoMono-Regular.ttf` is a
  14-byte placeholder ("404: Not Found") that `OpenTypeProvider` cannot parse — confirmed by
  `tools/test-opentype-provider.mjs` ("throws a clear error for a corrupt or unparsable font
  file"). All three manifest entries have `enabled: false`, but `FontManager.getFont()` and
  `getDefaultFont()` resolve by id regardless of `enabled` (only `listFonts()` filters on it),
  so the disabled flag does not block direct use by id.
* `app.js`'s `#font` control (`Rhinestone Mono Stroke` / `Rhinestone Mono Fill`) is stored on
  the layer but was never read by the bitmap generator — only `#textMode` (`stroke`/`fill`)
  selected between the two bitmap sampling routines. `#font` was decorative.
* Investigation during this task found a pre-existing defect unrelated to geometry: the
  per-control `input` listeners are wired as
  `el(id).addEventListener('input', updateAll)`. `addEventListener` invokes the handler with
  the DOM `Event` as its first argument, which becomes `updateAll`'s `skipWrite` parameter.
  Any object is truthy, so `if (!skipWrite) writeSelectedControlsToLayer()` was **always
  skipped** on typed/selected input, meaning edits to text, height, stone size, gap, colors,
  rotation/wrap/zoom text inputs, and shape X/Y/W/H never reached the project model. Verified
  with a headless-Chrome round trip against the unmodified baseline: dispatching an `input`
  event with new text left `#layoutStats` unchanged. This is fixed as part of this task (see
  "Implementation constraints") because it directly blocks demonstrating this milestone's core
  outcome — live regeneration in response to user edits — and the fix is a one-line, obviously
  correct change to how the existing listener is wired, not a redesign.

## Expected Visible Change

* Text layers render using real vector font outlines (Courier Prime or Great Vibes) instead of
  the fixed 5x7 bitmap grid. Letterforms look different; exact stone count and placement are
  expected to differ from the bitmap baseline.
* The `#font` control becomes functional: it selects between the two working bundled fonts
  instead of being a decorative label with two options that never affected generation.
* `#textMode` (`stroke`/`fill`) continues to exist and now maps to the permanent engine's
  `outline`/`fill` sampling modes, preserving its original "readable outline vs. dense fill"
  intent.
* Typing in the text box (and editing height/stone size/gap/colors/etc.) now visibly updates
  the layout live, which it did not reliably do before this task (see defect above).
* Shape layers (circle/rectangle), cup preview projection, exports, and the project JSON format
  are visually and structurally unchanged.

## Required Outcome

* `app.js` stops calling the legacy bitmap text path for `type === 'text'` layers.
* Text stones are produced by `new (permanent GeometryEngine)({ fontProviderRegistry }).generateTextLayout(...)`,
  fed by a `FontManager` built from `assets/fonts/manifest.json` and the default
  `OpenTypeProvider` registered via `createDefaultFontProviderRegistry`.
* 2D layout, cup preview, layer list/controls, shape generation, exports (Project JSON,
  Generated Layout JSON, SVG, PNG, Cup PNG), and the project JSON format continue to work.
* Stone geometry stays in millimeters end to end; `Stone.color` (the app's color key, e.g.
  `'gold'`) is preserved on every generated text stone.
* The legacy bitmap text path (`FONT5`, `generateText`, `sampleGlyphFill`, `sampleGlyphStroke`)
  remains present in `app.js`, unused for text, per "do not remove the legacy engine until all
  remaining dependencies are identified" — `line()` and the shape generators still depend on
  shared legacy helpers (`dedupe`, `bbox`, `line`), so the class is not fully separable yet.
* Visible output stays readable and stable; exact stone count is not required to match the
  bitmap baseline.

## Architecture Requirements

* `app.js` is the only file allowed to bridge DOM/project state to the permanent engine; the
  permanent modules (`src/geometry/**`, `src/text/**`, `src/fonts/**`) keep zero DOM/Canvas
  dependency (already enforced by existing tests).
* Text generation is asynchronous (`generateTextLayout` returns a `Promise`), so `app.js`'s
  `GeometryEngine.generate()` and `updateAll()` become `async`. A monotonic generation token
  guards against a slower, superseded generation overwriting a newer one when multiple
  generations are in flight (e.g. rapid typing).
* Auto-fit (`layer.autoFit`) is preserved by re-running `generateTextLayout` at a
  proportionally reduced `heightMm` when the natural layout is wider than the canvas, keeping
  `stoneSizeMm` fixed — matching the old behavior of shrinking glyph size, not the final stone
  layout, to fit.
* Centering: the generated `StoneLayout`'s bounding box is centered in the project canvas by
  translating stone coordinates by a fixed offset (a display-position transform, not a new
  geometry generation step); stone size and relative spacing are untouched.
