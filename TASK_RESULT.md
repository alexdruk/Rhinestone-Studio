## What changed in `src/geometry/GeometryEngine.js`

* Added `generateShapeLayout({ shape, layerId, stoneSizeMm, gapMm, mode, color, cxMm, cyMm,
  radiusMm })` (circle) / `({ shape: 'rectangle', ..., xMm, yMm, widthMm, heightMm })`
  (rectangle). It builds a `Contour` via the already-existing, already-tested
  `createCircleVectorPath()` / `createRectangleVectorPath()` helpers in `src/text/VectorPath.js`
  (unused by anything before this task), flattens it with the existing
  `flattenContourToPolygon()`, and samples it with the existing `sampleOutlinePoints()` /
  `sampleFillPoints()` — the same primitives `generateTextLayout()` already uses for glyph
  contours. No new sampling algorithm was written; this is a direct reuse/extension of the
  existing text pipeline to a second input shape.
* Returns a `StoneLayout` of `Stone` instances, identical in shape to what `generateTextLayout()`
  returns — text and shapes now produce the same permanent data structure, per the milestone's
  required outcome.
* `generateShapeLayout()` is synchronous (no font provider to await), unlike
  `generateTextLayout()`.
* The constructor's `fontProviderRegistry` is now optional (`{ fontProviderRegistry = null } =
  {}`), since shape generation never needs one. `generateTextLayout()` now throws a clear
  `TypeError` ("requires a fontProviderRegistry") if called without one, instead of the
  constructor throwing unconditionally. Added a `canGenerateText` getter so callers can check
  readiness without triggering that exception.
* Renamed the internal `TEXT_MODES` constant to `SAMPLE_MODES` (now shared by both text and shape
  param validation) — a same-file, contained rename.

## What changed in `app.js`

* `generate()`: `if(l.type==='circle')raw.push(...this.generateCircle(l));if(l.type==='rectangle')
  raw.push(...this.generateRect(l));` became `if(l.type==='circle'||l.type==='rectangle')
  raw.push(...await this.generateShapeStonesLive(l));`.
* Added `generateShapeStonesLive(layer)`, mirroring the existing `generateTextStonesLive(layer,
  project)`: maps the app's plain-object layer fields (`cx/cy/r` for circle, `x/y/w/h` for
  rectangle, plus `stoneSize`/`gap`/`color`) onto `generateShapeLayout()`'s parameter names, always
  requests `mode: 'outline'` (matching the shape UI's existing outline-only behavior — no fill
  mode is exposed for shapes, unchanged), and maps the returned `Stone[]` back onto the app's
  internal `{x,y,d,color,layerId}` shape used by the renderer/exporters (same conversion pattern
  already used for text).
* The legacy `generateCircle()` / `generateRect()` methods are **still present**, no longer
  called, per "do not remove the legacy engine until no live behavior depends on it" — `line()` is
  still shared with the legacy bitmap text stroke sampler, so the class is not yet fully
  separable (same situation `generateText`/`sampleGlyphFill`/`sampleGlyphStroke` were left in
  after RS-0003.5B3).
* Renamed the class field and top-level variable holding the permanent engine from
  `permanentTextEngine`/`permanentTextEngineError` to `permanentEngine`/`permanentEngineError`,
  since the engine is no longer text-only. Contained to `app.js`; not a public API.
* **Font-load resilience improvement**: previously, `permanentTextEngine` was only assigned
  inside the same `try` block that loaded the font manifest, so a font-manifest load failure left
  the permanent engine entirely unconstructed — which, after this migration, would have meant
  circle/rectangle generation failed too (a regression, since shapes never depended on fonts).
  Fixed by restructuring startup: `FontManager.fromUrl(...)` /
  `createDefaultFontProviderRegistry(...)` failure now only leaves `fontProviderRegistry` as
  `null`; `new PermanentGeometryEngine({ fontProviderRegistry })` (now always safe per the
  constructor relaxation above) still runs, so shape generation is unaffected by a font-loading
  failure. `generateTextStonesLive` now checks `this.permanentEngine.canGenerateText` before
  calling `generateTextLayout()`, returning `[]` gracefully instead of letting the new "requires a
  fontProviderRegistry" error abort the whole `generate()` call (which would otherwise also wipe
  out shape stones generated earlier in the same pass). Verified in browser testing (see below).
* Status message updated: `Font manifest failed to load (...); text layers are empty. Shape
  layers are unaffected.` (previously implied text-only impact anyway, but is now explicit and
  accurate).

## Incidental fix: forbidden-file-check path parsing bug

While updating the "no forbidden file changed" guard tests, found and fixed a pre-existing bug
present in all four `tools/test-*.mjs` files that have this check
(`test-app-module-migration.mjs`, `test-browser-dependency-loading.mjs`, `test-geometry-engine.mjs`,
`test-live-text-integration.mjs`): each did `.map(line => line.trim()).filter(Boolean).map(line =>
line.slice(3).trim())` on `git status --porcelain` output. `git status --porcelain` lines are
always exactly two status characters + one space + the path (e.g. `" M src/geometry/..."`).
Calling `.trim()` **before** `.slice(3)` strips the line's leading space first for the common
single-letter-in-column-2 case (` M `, ` D `, etc.), so `.slice(3)` then over-strips by one
character and truncates the real path (` M src/geometry/x.js` → trimmed to `M src/geometry/x.js`
→ sliced(3) to `rc/geometry/x.js`), which never matches any `startsWith(prefix)` check. This
silently made the "no forbidden file changed" guard a no-op for any **modified** (not new/staged)
file in every one of these four test files — confirmed directly: before the fix, `git status
--porcelain` showed `src/geometry/GeometryEngine.js` as modified while the (still-listing-
`src/geometry/`-as-forbidden) old test reported "✓ no forbidden file changed" anyway. Untracked
(`??`) files were unaffected by the bug (their two-character status is followed by a real second
space, so the arithmetic happens to work out). Fixed by slicing the untrimmed line and only
trimming the filter/output steps, in all four files. This is included because it directly
undermines the specific safety mechanism this milestone is required to rely on and update; it is
a one-line parsing fix, not a design change, matching the precedent set by RS-0003.5B3's
`skipWrite` fix (an incidental, directly-required correctness fix, not general cleanup).

# Visible Changes

* Circle and rectangle layers now render using the permanent Geometry Engine's contour-flattening
  and outline-sampling pipeline instead of trigonometric/line-walk placement. Visually
  indistinguishable stone spacing/appearance at normal stone sizes; exact point positions differ
  by sub-manufacturing-tolerance amounts.
* Shape editing (add, select, move, resize, duplicate, delete, visibility) is unchanged in
  behavior — verified via the browser session above.
* A shape-only project (or a project where font-manifest loading fails) now renders its shapes
  correctly even when text generation cannot run — previously, shapes were unaffected by font
  loading because they used a fully independent legacy code path; this milestone's unification
  under one engine could have introduced that coupling, so it was explicitly designed out (see
  "Font-load resilience improvement" above) and verified in browser testing.
* Text layers, cup preview, exports, and the project JSON format are visually and structurally
  unchanged.

# Known Limitations

* `app.js`'s ad hoc project/layer object shape was not migrated to `src/core/Project.js` /
  `Layer.js` — out of scope for this milestone, as it was for RS-0003.5B3.
* The legacy bitmap text engine and the now-dead legacy shape generators are still present,
  unused, in `app.js`. A follow-up milestone should confirm nothing else depends on either path
  and then delete both together (they share `line()`/`dedupe()`/`bbox()`).

  sampler exactly as text does), but `app.js` never requests it — there is no shape fill mode in
  the UI, matching pre-existing shape behavior. Adding one is a candidate for a future milestone,
  not attempted here.
* PNG/Cup PNG export byte content was smoke-checked (real `image/png` blob, non-trivial size) but
  not pixel-inspected in this session.
